## 技术结构

- GitHub Pages 静态网站：天津心血管疾病+队列
- Supabase Auth 密码/TOTP；项目成员白名单；活动AAL2会话
- Supabase PostgreSQL 私有 schema `clinical_private`：313原始字段和内部行号
- 管理员专属首次CSV导入：SHA-256同文件识别、每批150行、网络中断后可重试
- 字段权限：默认不向普通成员提供患者级字段；管理员最多审核开放15项
- 研究成员：服务器端分页25条上限、查询频率限制、操作审计、少于5人的统计分组不单独显示
- 不提供整库CSV/Excel下载；已显示的信息不能保证绝对防截图或复制

## 数据接入状态

截至部署时，真正患者记录的入库数仍为 **0**。管理员需要在网站登录后通过`选择CSV`完成一次受控上传。
这一步由浏览器直接通过TLS访问Supabase RPC；聊天运行环境不能直接向数据库传输本地113MB文件。
入库结束后成员跨设备共用同一份数据库，无需再次上传。

现有项目区域位于日本东京；实际传输医疗数据前须确认数据所有者允许该境外存储与处理。
Supabase Free不提供与付费方案同等的自动备份保障，真实数据需要额外备份。
